# Подготовка подключений

Локальный мастер `bootstrap.py` создаёт Telegram-сессию reader, выбирает начальный канал и привязывает владельца управляющего бота. Распознавание, Web UI и локальное paper-исполнение реализованы. Live-контур присутствует, но требует отдельного приватного ключа, read-only проверки и явной активации по инструкции в README.

## Запуск мастера на этом компьютере

Зависимости установлены в `.venv`. Откройте `setup-local.cmd` двойным щелчком из папки проекта.
Он проверит настройки, запросит код Telegram и пароль 2FA (ввод скрыт), предложит выбрать начальный канал.
Затем покажет одноразовую команду `/start ...`: отправьте её управляющему боту с личного аккаунта и подтвердите отображённый ID в локальном окне словом YES.
ID канала и владельца сохраняются в `.env`. Мастер не отправляет сообщения каналов в модель и не совершает сделки.

Проверки из PowerShell в папке проекта:

```powershell
.\.venv\Scripts\python.exe bootstrap.py check
.\.venv\Scripts\python.exe bootstrap.py network --llm
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

`network --llm` отправляет один короткий платный запрос к модели, без содержимого каналов. Это отдельная проверка, не часть повторяемого интерактивного мастера.

## Пользователь Telegram

1. На https://my.telegram.org войдите под своим аккаунтом разработчика. Можно использовать уже созданное собственное приложение с основного аккаунта; TELEGRAM_PHONE и сессия при этом относятся к отдельному аккаунту-читателю.
2. В API development tools создайте приложение: например, title `TG Trader`, short name `tgtrader`, platform Desktop, description `Personal Telegram channel reader`.
3. Сохраните api_id и api_hash в локальный `.env`, поля TELEGRAM_API_ID / TELEGRAM_API_HASH. TELEGRAM_PHONE — номер выделенного аккаунта в международном формате.
4. Через обычный Telegram вступите этим аккаунтом в первый приватный канал для проверки. Права администратора читателю не нужны.
5. При первом подключении программы код входа и пароль 2FA вводятся локально интерактивно. Не записывайте их в `.env` и не отправляйте в переписку. Сессия будет храниться в data/telegram/.

## Управляющий бот

1. Откройте https://t.me/BotFather и выполните /newbot.
2. Задайте отображаемое имя и свободный username, заканчивающийся на bot.
3. Сохраните выданный токен в TELEGRAM_BOT_TOKEN локального `.env`.
4. Откройте нового бота с личного аккаунта владельца и нажмите Start. До запуска приложения он не отвечает.
5. Добавлять управляющего бота в каналы сигналов не нужно.
6. TELEGRAM_OWNER_ID — числовой ID личного аккаунта владельца. Его заполнит мастер через одноразовую команду и локальное подтверждение. Доступ при пустом ID должен быть закрыт, не разрешён всем.

## OpenAI API

1. Войдите на https://platform.openai.com/ и создайте отдельный проект `tg-trader` через выбор проектов.
2. В настройках Billing подключите оплату API и, если доступна предоплата, пополните на 10 USD для первого теста. Проверьте настройки автоматического пополнения.
3. Выбрав проект, откройте https://platform.openai.com/api-keys и создайте secret key с названием `tg-trader-local`.
4. Сохраните ключ в OPENAI_API_KEY локального `.env`. Организационный admin key не нужен.
5. При настройке restricted permissions разрешения должны допускать вызов Responses API; конкретный набор проверим при первом подключении.
6. Установите бюджет/уведомления проекта на 20 USD, если доступны. Приложение дополнительно проверяет `LLM_MONTHLY_BUDGET_USD` перед запросом и резервирует консервативную сумму на неоднозначный сбой. Это не заменяет лимиты и уведомления провайдера.
7. Наличие ключа ещё не подтверждает доступ к выбранной модели. Команда `bootstrap.py network --llm` проверяет доступ отдельным коротким платным запросом.

## Локальные настройки и начальный канал

Заполняйте `.env`, а не `.env.example`. `.gitignore` исключает `.env`, пользовательские сессии, data/ и logs/ из будущего Git-репозитория; это не шифрование файлов. Не пересылайте эти файлы и не прикладывайте скриншоты с секретами.

Числовой ID начального приватного канала мастер получает из списка каналов после авторизации. До запуска `TELEGRAM_TEST_CHANNEL_ID` можно оставить пустым. После настройки дополнительные каналы добавляются в разделе «Каналы» Web UI по ID; аккаунт reader должен быть на них подписан.

В проверочном канале публикуйте вход и обновление отдельными сообщениями, связывая обновление реальным Reply. Загрузите несколько оригинальных картинок и JPG как файлы. Это позволит проверить метаданные Telegram, а не только нарисованный реплай на скриншоте.

Для первого paper-режима ключи MEXC не требуются.

Для приватной проверки добавьте в `.env` `MEXC_API_KEY`, `MEXC_API_SECRET`, `MEXC_RECV_WINDOW_SECONDS=10`. Значение `MEXC_LIVE_ORDERS_ENABLED=NO` разрешает только чтение приватного аккаунта. Точное `YES` открывает в reader возможность принять отдельную Live-активацию; само по себе оно режим Live не включает.
