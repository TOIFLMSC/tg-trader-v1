# TG Trader — Telegram signals, paper trading and guarded MEXC Live

TG Trader читает новые сообщения из приватных Telegram-каналов через отдельный пользовательский аккаунт, распознаёт текст и изображения мультимодальной моделью, связывает реплаи с исходными сигналами и формирует детерминированные торговые планы. Управлять подтверждениями, каналами, банками и режимами можно через отдельного Telegram-бота и локальную Web-панель.

Поддержаны три режима исполнения:

| Режим | Поведение |
| --- | --- |
| `recognition` | Только чтение, распознавание и торговые планы; заявок нет. |
| `paper` | Сделки симулируются на публичных рыночных данных MEXC и виртуальном балансе. |
| `live` | Реальные Futures-заявки MEXC через отдельный защищённый контур. |

Распознавание на LLM не имеет доступа к биржевым ключам и не исполняет сделки. Символы, размеры, плечо, isolated margin, reduce-only и состояние позиции проверяет обычный код. Live отключён по умолчанию и требует одновременно разрешающей настройки, свежей read-only проверки аккаунта, ручной фразы активации и выбора режима `live`.

> **Статус:** это персональный прототип торговой автоматизации. Paper-контур покрыт тестами; guarded Live реализован, но требует осторожной приёмки минимальной суммой на реальном аккаунте. Использование кода не является инвестиционной рекомендацией.

## Быстрый запуск на Windows

Понадобятся Windows 10/11, Python 3.12, Telegram API credentials, токен управляющего бота и OpenAI API key. Ключ MEXC не нужен для режимов `recognition` и `paper`.

```powershell
git clone https://github.com/TOIFLMSC/tg-trader-v1.git
cd tg-trader-v1
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

1. Заполните локальный `.env`. Назначение полей описано в [`.env.example`](.env.example), подробная подготовка аккаунтов — в [`docs/setup.md`](docs/setup.md).
2. Запустите `setup-local.cmd`. Мастер проверит настройки, создаст локальную Telegram-сессию, предложит выбрать начальный канал и безопасно привяжет владельца управляющего бота.
3. Запустите `start-all.cmd`. Reader начнёт читать новые сообщения, а панель откроется на `http://127.0.0.1:8787`.
4. Начинайте с `recognition`, затем проверьте полный сценарий в `paper`. Порядок отдельной активации Live приведён ниже.

Все секреты остаются в `.env`. Telegram-сессия, базы, изображения каналов, журналы и PID-файлы сохраняются в `data/` и `logs/`; эти пути исключены из Git. Не копируйте их в issue, PR или архив проекта.

## Повседневный запуск и управление

1. Запуск reader в видимом окне: `start-recognition.cmd` (оставить окно открытым).
2. Запуск reader без окна: `start-recognition-background.cmd`. Это локальный фоновый процесс, а не автозапуск Windows; после перезагрузки его нужно запустить снова.
3. Состояние: `status-recognition.cmd`. Живой журнал: `watch-recognition-log.cmd`.
4. Остановка: Ctrl+C в видимом окне или `stop-recognition.cmd`.
5. Команды бота: `/status`, `/pending`, `/plan ID`, `/approve ID VERSION`, `/skip ID VERSION`, `/adjust ID VERSION ...`, `/pause`, `/resume`.

Локальный Web UI:

1. `start-ui.cmd` запускает только панель на `http://127.0.0.1:8787`.
2. `start-all.cmd` проверяет/запускает Telegram reader, открывает браузер и оставляет UI в видимом окне.
3. `stop-ui.cmd` останавливает только UI; `stop-all.cmd` — UI и reader.
4. Закрытие окна UI не останавливает Telegram reader.

Панель показывает heartbeat процессов, режимы и счётчики событий. Раздел «Каналы» позволяет добавить канал по Telegram ID, включить или отключить его мониторинг, сохранить выделенный банк и размер входа. Reader проверяет, что пользовательский Telegram-аккаунт действительно видит добавляемый канал. В «Постах» доступны фильтры, изображения, исходный текст, структурированный разбор и история повторных разборов. «Статистика» показывает результаты распознавания, расход LLM, win rate, PnL, доходность банков, drawdown, комиссии, funding и кривую накопленного paper PnL. График имеет денежную ось USDT и календарную ось с режимами 30 дней, 12 месяцев и 10 лет.

В разделе «Управление» можно приостановить LLM-разбор, выбрать manual/auto approvals и переключить исполнение между recognition и paper. Пауза не прекращает чтение Telegram: новые посты сохраняются в очередь. Переключение влияет только на новые планы; ожидающие paper trigger-limit замораживаются в recognition и продолжаются после возврата в paper. Live включается отдельным сценарием: read-only проверка приватного аккаунта, точная фраза `LIVE <snapshot id>`, затем переключение режима. Проверка действует 5 минут. Выход из Live или ошибка приватной сверки сразу снимает защёлку. Неисполненный подтверждённый Live-план возвращается на новую версию и требует повторного ручного подтверждения после активации. На первом этапе Live разрешён только с ручными подтверждениями.

В «Сделках» показаны спецификация MEXC, котировка, виртуальные заявки, позиции, занятая маржа, mark price, realized/unrealized PnL, funding, комиссии, SL и TP. Позиции, заявки и планы имеют независимую пагинацию по 10 записей; выбранные страницы сохраняются при фоновом обновлении и после действий. Ожидающую или уже сработавшую, но ещё не исполненную trigger-limit заявку можно отменить версионированной командой через reader. Если после перерыва порядок пересечения защитных уровней неизвестен, позиция показывает `attention`, исходную минутную свечу и возможные исходы; владелец может продолжить наблюдение с текущей цены. Manual требует подтверждения каждого действия. Auto подтверждает только полные свежие paper-планы с успешной MEXC-проверкой; старые сигналы и вопросы остаются ручными.

«Сделки» фоново обновляются каждые 3 секунды, «Статистика» — каждые 10 секунд. Если открыта форма ручной корректировки плана, обновление приостанавливается, чтобы не потерять введённые значения.

Читаются только новые посты включённых каналов и до трёх исходных сообщений в цепочке реплаев. Для теста после запуска опубликуйте новый сигнал, затем ответьте на него через Reply. История каналов автоматически не выгружается.

Поддержаны фото и изображения JPG/PNG/WebP как документы, альбомы, правки постов. Ограничения: до 8 MB на картинку и до 12 картинок вместе с контекстом. Неподдерживаемое медиа отмечается для ручного разбора. Графики с мелкими цифрами могут потребовать уточнения.

## Устройство

- `trader/service.py`: Telegram-события, доступ владельца, уведомления, один процесс на проект.
- `trader/agent.py`: до четырёх шагов агента; инструменты просмотра предыдущих разборов и сохранения нового результата. Нет инструмента исполнения сделок.
- Числа в схеме инструмента заданы без единиц (`20`, не `20x`). При ошибке валидации разрешён один запрос исправления в пределах четырёх шагов. Аргументы вызовов и ошибки по полям сохраняются локально в `agent_attempts`, без API-ключей и HTTP-заголовков. Некорректные ответы не становятся действиями.
- Для сопровождения без Telegram Reply агент всегда получает структурированные кандидаты ранее распознанных входов. Код независимо сопоставляет действие по исходному посту, стороне, цене открытия автора и плечу. Похожий тикер сам по себе недостаточен для исправления. Старые результаты ручного переразбора сохраняются в `analysis_revisions`.
- `trader/models.py`: схема результатов и проверка чисел, форматирование карточки.
- `trader/planner.py`: детерминированная проверка сигнала, расчёт маржи и плеча, trigger-limit, владение позицией и причины блокировки. Модуль не имеет доступа к бирже.
- `trader/mexc_market.py`: read-only адаптер публичного Futures API MEXC. Проверяет наличие и активность USDT perpetual, доступность API и isolated, диапазон плеча, шаги цены, минимальный объём, котировку и историю старых сигналов. Ключ MEXC ему не передаётся.
- `trader/mexc_private.py`: приватная HMAC-подпись MEXC без автоматических повторов write-запросов. Секрет остаётся только в памяти процесса.
- `trader/live.py`: readiness, persisted Live state machine, isolated/reduce-only payloads, `externalOid`, сверка неизвестных результатов и автоматическое снятие защёлки при расхождении.
- `trader/paper.py`: локальный paper executor. Исполняет одобренные market и trigger-limit планы, ведёт fills/positions, reduce-only закрытия, маржу, комиссии, funding, PnL, стопы и одиночный TP, а после перерыва проверяет защитные пересечения по минутным свечам. Приватных вызовов MEXC в модуле нет.
- `trader/store.py`: локальная SQLite-база событий/разборов/расхода. Версионированные миграции находятся в `trader/migrations.py`; PostgreSQL для дальнейшего торгового сервиса остаётся в плане.
- `trader/webapp/`: локальная FastAPI/Jinja2 панель состояния. Она слушает только `127.0.0.1` и не показывает секреты.
- `bootstrap.py`: проверка подключений, авторизация и локальная привязка владельца.

Данные, изображения, сессия, база и логи хранятся в исключённых из Git `data/` и `logs/`. Секреты читаются из `.env`; модель их не получает. Текст каналов и результаты инструментов трактуются как недоверенные данные.

Основной журнал находится в `logs/recognition.log`, stderr — в `logs/recognition-error.log`, PID текущего процесса — в `data/recognition.pid`. При фоновом старте файлы журналов относятся к текущему запуску. Набор ручных проверок находится в `docs/recognition-test-cases.md`.


```powershell
.\.venv\Scripts\python.exe -m tests.smoke_paper_public
```

```powershell
.\.venv\Scripts\python.exe -m tests.smoke_live
```

Если есть `data/smoke/br-entry.png`, тест проверяет исходный пользовательский скриншот BR и закрытие по реплаю, иначе — искусственный текстовый пример. Не запускать автоматически при каждом старте.

Безопасный ручной повтор разбора одного сохранённого события записывает результат в `data/replay-result.json`, не меняя событие и не отправляя уведомление:


## Подключение приватного MEXC API

1. В MEXC откройте управление API и создайте отдельный ключ для этого приложения. Аккаунт должен пройти KYC; для ключа нужны просмотр аккаунта/ордеров и futures trading. Вывод средств не включайте. Для VPS привяжите фиксированный IP.
2. Запишите ключ и secret в `.env` как `MEXC_API_KEY` и `MEXC_API_SECRET`. Сначала оставьте `MEXC_LIVE_ORDERS_ENABLED=NO`, перезапустите reader и нажмите «Проверить MEXC» в «Управлении». Это выполняет только read-запросы.
3. Проверка блокируется при нулевом доступном USDT, режиме позиции не `hedge`, cross-позиции или позиции/заявке, которую приложение не создавало. Для первого включения используйте пустой futures-аккаунт и hedge mode.
4. После успешной проверки остановите reader, установите точное значение `MEXC_LIVE_ORDERS_ENABLED=YES`, снова запустите reader, повторите проверку, введите показанную фразу `LIVE <id>` и только затем выберите Live. Все первые действия подтверждайте вручную.

Ключи не сохраняются в SQLite и не отображаются в Web UI. Официальные требования к подписи и правам: [MEXC Futures integration guide](https://www.mexc.com/api-docs/futures/integration-guide).

## Ограничения текущего этапа

- Live реализован как ранний guarded-контур и по умолчанию выключен. До контролируемого теста минимальной суммой он не считается проверенным против реального аккаунта. Частичные fills сверяются по ордеру, но полная Live-статистика комиссий/funding и управление несколькими TP ещё не завершены; Live TP принимает ровно одну цель на подтверждённый план.
- Симуляция применяет taker-комиссию контракта ко всем исполнениям, включая trigger-limit, чтобы не завышать результат. Если MEXC не вернул комиссию или maintenance margin, paper executor не подставляет ноль. Mark price и условия SL/TP/ликвидации проверяются примерно раз в две секунды. Funding рассчитывается по публичной истории settlement: ставка умножается на стоимость остатка позиции по текущей цене в момент обработки, потому что endpoint истории не возвращает историческую fair price. Это приближение явно сохраняется как `last_price_at_processing`. Для нескольких TP без долей закрытия система уведомляет владельца и не меняет позицию; один TP закрывает остаток полностью.
- Ожидающий trigger-limit не заменяется рынком и замораживается при переключении в recognition. Его можно вручную отменить на странице «Сделки»; команда проходит через reader, проверяет версию и записывается в аудит.
- Сохранённые планы, заявки и позиции продолжают работу после перезапуска. Для открытой позиции перерыв от минуты проверяется по минутным свечам MEXC: однозначный первый защитный исход исполняется по уровню, а несколько исходов в одной свече, частично перекрытая свеча или разрыв свыше 2000 минут переводят позицию в `attention`. Историческое срабатывание ожидающего trigger-limit во время полного отключения пока не реконструируется. Посты, опубликованные во время полного отключения приложения, автоматически не догружаются. Не использовать как торговую систему.
- Уведомления доставляются с повторными попытками; после сбоя на границе отправки/сохранения возможна повторная карточка. Write-запрос MEXC не повторяется автоматически: сетевой сбой после отправки переводит заявку в `unknown`, снимает Live-защёлку и запускает read-only сверку по `externalOid`.
- Бюджет учитывает токены по тарифу Luna $0.20/$1.20 за миллион (проверен 19.09.2026). Перед запросом резервируется $0.25; при неизвестном результате резерв сохраняется. Это локальная оценка, не гарантия ограничения выставленного провайдером счёта. При смене модели/тарифа нужно обновить расчёт.
- Приложение читает только явно включённые в локальной панели каналы, доступные аккаунту reader. Ответственность за право передавать их содержимое внешней модели остаётся у владельца системы.

Дальше: проверка read-only readiness на вашем ключе, ревью сохранённого snapshot, затем отдельно разрешённая минимальная Live-сделка. После неё — сверка комиссий/funding, частичных fills и расширение auto-режима.
